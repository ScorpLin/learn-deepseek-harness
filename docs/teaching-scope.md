# Teaching Scope（教学范围）

这一页明确「教什么、不教什么、怎么教」，是整条教学线的契约。对应参考项目 learn-claude-code 的 teaching-scope。

## 教学目标

一句话：**理解这套 harness 的「设计主干」，理解到你能自己重建它。**

「设计主干」= 决定 agent 能不能跑好的机制，而不是产品的每个角落。对 DeepSeek Harness 而言，主干是：

Cordis（底座）→ 事件/服务（神经）→ capability seam（可替换）→ agent loop + session log（心脏）→ tools + prompt assembly（手与嘴）→ scope（隔离）→ skill/subagent/workflow/permission/sandbox（平台化）。

## 四条教学规则（贯穿全书）

1. **先解释，再使用** — 一个概念在它第一次被依赖之前，一定已经完整讲过。
2. **一个概念只在一处完整讲透** — 别处只引用、链接回「家」，不重复展开。
3. **是什么 → 为什么 → 怎么做** — 每章的固定三段式。
4. **贴近真实源码** — 每章给「源码锚点」，指到 `vendor/` 和 `packages/` 的具体文件，不空谈。

## 每章的统一结构

| 段落 | 回答 |
|---|---|
| 一句话 | 这章讲的那个机制，用一句话说清 |
| 是什么 | 它是什么，长什么样（带最小代码） |
| 为什么 | 它解决什么问题，没有它会怎样 |
| 怎么做 / 怎么用 | 可运行例子（阶段一、工具章）或源码精读（其余章，追 Definition→Provider→Consumer） |
| 读源码 | 指到具体文件 + 关键行，逐段精读 |
| 自测 | 3-5 个「你应该能答上来」的检查点 |

## 刻意不教

不把与「agent 核心运行模型」无关的细节放进主线：

- 打包发布（`pnpm publish`、release 脚本）
- 跨平台兼容（Windows/wine、CI 矩阵）
- 企业胶水（遥测、账号、审计接线）
- 历史兼容分支与命名事故

这些可能在生产里重要，但会把 0→1 主线带偏。

## 四阶段边界

| 阶段 | 范围 | 学完的标志 |
|---|---|---|
| **1 地基** s01-s04 | Cordis：插件/事件/服务/配置 | 能读懂 `examples/headless-agent/cordis.yml` 每一行 |
| **2 主干** s05-s09 | seam + loop + log + tools + prompt | 能手绘 turn flow 时序图，说清「模型可见⟺已记录」 |
| **3 动手** s10-s14 | scope + adapter + 写工具 + subagent + skill | 能从零写一个带执行管线的最小工具 |
| **4 平台** s15-s19 | workflow + 权限 + goal/plan + 沙箱 + 扩展 | 能设计一条新的 capability seam 并解释三角色 |

每阶段结束，**停下来自己重建一遍最小版本**，再进下一阶段。

## 与官方文档的分工

- 官方 `docs/`：按系统结构组织的**参考手册**（架构、子系统、catalog）。
- 本仓库：按**依赖顺序**组织的**教程**。

两者不重复：本仓库负责「带你走一遍」，官方文档负责「你随时查权威细节」。
